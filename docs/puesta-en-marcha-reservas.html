Flor del Bosque · Sistema de reservas

Puesta en marcha

El código está escrito y probado. Faltan las dos cuentas que sólo tú puedes configurar. Son unos veinte minutos, en este orden.

Fase 1

La base de datos

airtable.com

  1. Crear la base

    Una base nueva llamada Flor del Bosque, con dos tablas. Los nombres de tabla y de campo importan: el código los busca exactamente así, en minúsculas y sin tildes.

    Toda tabla de Airtable nace con un campo primario llamado Name que no se puede borrar. En Habitaciones renómbralo a nombre, y en Reservas a huesped, en vez de crear campos aparte.

  2. Tabla Habitaciones

  3. Tabla Reservas

    CampoTipoNota

    Los tres estados deben escribirse tal cual. Solicitud y Confirmada ocupan la pieza; Cancelada la libera. Si escribes otra cosa, esa reserva no bloqueará nada.

    El campo habitacion, paso a paso

    Agregar campo → tipo Link to another record → elegir la tabla Habitaciones. Luego, en las opciones del campo, desactivar «Allow linking to multiple records».

    Una reserva es una pieza. Si permites varias, alguien podría vincular dos habitaciones a un mismo registro y quedarían ambas bloqueadas por una sola reserva.

    Airtable creará solo un campo recíproco en Habitaciones, llamado Reservas. Déjalo: el código ignora los campos que no conoce. Y como el selector muestra el campo primario de la tabla vinculada, si renombraste el primario a nombre verás «Vista Volcán» al vincular, en vez de una fila en blanco.

    Las fechas van sin hora

    El campo Date trae un interruptor «Include time». Debe quedar apagado. Con la hora encendida, Airtable manda 2026-09-12T00:00:00.000Z en vez de 2026-09-12.

    El código ahora tolera ambas formas, pero la correcta es sin hora: el check-in y el check-out son días, no instantes.

  4. Cargar las habitaciones

    Las siete, con precio_noche vacío en todas. Cuatro salen de la página de alojamiento actual:

    idnombrecapacidadm²orden
    vista-volcanVista Volcán2351
    bosqueHabitación Bosque2252
    familiarSuite Familiar4453
    rioHabitación Río2254
    Las otras tres las necesito de ti. No existen en ninguna parte del sitio ni del repositorio. Por cada una: id, nombre, categoría, capacidad, m², descripción y una foto. Van con orden 5, 6 y 7.

  5. Vista de seguimiento

    En Reservas, una vista llamada Solicitudes sin resolver: filtro estado = Solicitud, ordenada por fecha de creación.

    Sirve para algo concreto: como las solicitudes ocupan la pieza, una que nadie responda la mantiene bloqueada. Esta vista te las muestra para que las canceles.

  6. Crear el token

    En airtable.com/create/tokens, un Personal Access Token con permisos data.records:read y data.records:write, y acceso sólo a la base Flor del Bosque.

    Anota también el Base ID: aparece en la URL de la base y empieza con app.

Fase 2

El servicio

dash.cloudflare.com

  1. Confirmar el correo de destino

    En Email Routing → Destination addresses, que hola@flordelbosque.cl figure como Verified.

    El Worker envía las solicitudes por ahí. Si no está verificada, rechaza el envío.

  2. Crear el widget de Turnstile

    En Turnstile, un widget para el dominio flordelbosque.cl. Te da dos llaves distintas y ambas se usan en lugares distintos.

  3. Pegar la Site Key en el sitio

    En pages/reservas.html, reemplazar el texto REEMPLAZAR_CON_LA_SITE_KEY por la Site Key. Es pública, va en el HTML.

  4. Crear la caché

    cd worker
npx wrangler kv namespace create CACHE

    Imprime un bloque con id = "...". Ese id reemplaza a REEMPLAZAR_CON_EL_ID_REAL en worker/wrangler.toml.

  5. Cargar los tres secretos

    npx wrangler secret put AIRTABLE_TOKEN
npx wrangler secret put AIRTABLE_BASE_ID
npx wrangler secret put TURNSTILE_SECRET
    Estos tres nunca van a un archivo del repositorio. El token de Airtable en particular da acceso de lectura a la tabla completa, con los nombres, correos y teléfonos de tus huéspedes.

  6. Publicar

    npx wrangler deploy

    Cloudflare crea solo el registro DNS de reservas.flordelbosque.cl. Puede tardar un minuto en responder. Para comprobarlo:

    curl -s https://reservas.flordelbosque.cl/api/disponibilidad

    Debe devolver tus habitaciones, cada una con "precio_noche": null y "ocupado": [].

Turnstile tiene dos mitades y hacen falta las dos

La Site Key va en el HTML y el Secret va en el Worker. Si desplegas el Worker pero olvidas pegar la Site Key, el formulario se envía y falla la validación.

El síntoma no apunta al problema: se ve como un error de envío, no como una llave faltante. Si algo falla al probar, revisa esto primero.

Cuando termines, avísame

Con esto puedo cerrar lo que queda:

  • Los datos de las tres habitaciones que faltan, para publicarlas en la página de alojamiento
  • Que el Worker ya responde, para correr la verificación de punta a punta
  • Si el correo de prueba llegó y si cayó en spam, que es el único riesgo que no pude descartar
